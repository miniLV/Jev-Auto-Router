Jev 自动切换 Codex 模型
逐调用技术设计

同一个 Codex 任务、同一个工具循环。每次模型调用由 Jev 选择可执行的模型与推理档位；本地路由器负责校验、应用和原样转发 Responses 流。工具执行仍由 Codex 管理。

方案 A：本地 Responses 路由 A→B→A：用户报告已通过 产物：供 Review 的设计稿
设计前提：已存在可工作的认证 caller edge，并已在真实 Codex 会话完成跨模型工具循环。本文把该结果作为用户提供的前提；没有在此文档中重新执行或复核测试。此稿提出新架构，不声明现有仓库实现已经符合它。
01

系统拓扑：一次调用走哪条路

主线只处理 Codex 原生 Responses 请求；Jev 是路由决策支线，不接触上游认证凭据。

HOST

Codex CLI

保留一个会话与工具循环；请求目标为虚拟模型 jev/auto。

→
LOCAL ENTRY

Codex Router

识别 jev/auto，把 Responses 请求交给本地 Jev Router。

→
DECIDE + APPLY

Jev Router

提取准许发送的事实；构造候选；校验选择；只改 model 与 reasoning.effort。

→
AUTHENTICATED EDGE

Caller edge

用已经验证的原生认证通道发送真实模型请求；禁止再次路由到 jev/auto。

→
EXECUTION

GPT 模型

实际执行本次调用；SSE 响应沿原路即时返回 Codex。

↕
ROUTING INTELLIGENCE

TypeSafe Jev

接收白名单状态与可用的 (model, effort) 候选；返回一个选择及置信度。不接收完整请求、工具输出或认证凭据。

原生 Responses 请求与 SSE有限路由事实与 Jev 决策

核心约束：用户内容只通过本地代理到达原本要调用的 GPT 上游；Jev 路径只携带允许发送的结构化事实。虚拟模型入口与认证 caller edge 必须分开，以避免递归转发。

02

六个模块，各自负责什么

接口尽量小：决策、实际执行和观测分开，避免第二个隐藏选模器。

M1 / INGRESS

请求接入

接收 Codex Router 转来的 Responses 请求；识别当前会话、调用类型、用户指定模型与基础设施调用。保留原始请求供转发。

输出：CallContext + 原生请求
M2 / ADMISSION

候选与隐私

从已验证可请求的模型清单生成候选组合；应用用户硬约束；只提取经白名单批准、足以决策的路由事实。

输出：RoutingFacts + CandidatePairs
M3 / JEV CLIENT

一次 Jev Choice

用固定版本、固定问题模板在候选组合中选择一个。只做一次有截止时间的调用；返回 pair ID 与置信度。

输出：ProposedPair 或失败原因
M4 / GUARD + APPLY

校验并应用

检查候选成员、当前可用性、用户约束和置信度。决定实际组合后，仅覆盖请求中的模型与 effort。

输出：AppliedRequest + RouteSource
M5 / RELAY

认证与流转发

调用已验证的 caller edge；响应字节边到边转发；取消同步传给上游。开始输出后不自动重放。

输出：原生 SSE / JSON 响应
M6 / OBSERVE

被动观测

记录提议组合、应用组合、上游实际模型、耗时、用量与失败原因；缺失值标为 UNKNOWN，不记录原文。

输出：每次调用的审计记录
03

Codex 与 Jev 怎样交互

Jev 不成为 Codex 的执行模型。它只在上游模型调用之前，给本地路由器一个受约束的选择。

响应传回时不等待整段生成完成。观测模块旁路读取完成事件；观测失败不阻断或改写 Codex 收到的响应。

04

业务流程：从用户任务到交付

模型每调用一次，就经历一次轻量路由；工具调用本身不经 Jev 决策。

回退只在发出上游请求之前决定。若上游已经开始输出，网络中断直接作为该次调用失败上报，不在同一调用上自动改模型重放。

05

模型怎么路由，怎么 Apply

Jev 返回建议；本地 Guard 决定它能否执行；Apply 只改变本次请求的两个字段。

ROUTE / BEFORE JEV

候选集合与输入

  • 可用组合：来自认证通道实际可请求的模型与 effort；每个候选是完整的 (model, effort) 对。
  • 硬约束：用户手动固定模型直接执行；基础设施调用使用固定组合；不符合能力与可用性要求的组合先排除。
  • 送给 Jev：调用类型、当前模型、上下文区间、工具名称与状态、错误类别等白名单事实。任务摘要只有明确允许发送时才可加入。
  • 不送 Jev：原始用户文本、工具输出、完整会话、代码文件内容与认证信息。
DECIDE / AFTER JEV

校验、回退与记录

  • Jev 回答：一个候选 pair ID 与置信度；模型和 effort 不分开拼接。
  • Guard：检查 pair ID 属于当前候选、模型仍可请求、用户约束未被覆盖、置信度达到已校准阈值。
  • 失败回退：使用事先验证的可靠组合，例如 Sol/medium；不可用则在发送前明确失败。用户固定模型不会被回退降级。
  • 记录：区分 Jev 提议、实际应用和上游报告的真实模型；未知用量保留 UNKNOWN。
Codex 发出的请求 · 示意
{
  "model": "jev/auto",
  "reasoning": { "effort": "medium" },
  "input": "…",
  "tools": ["…"],
  "stream": true
}
→
Apply 后发给 caller edge · 示意
{
  "model": "gpt-5.6-sol",
  "reasoning": { "effort": "high" },
  "input": "…",
  "tools": ["…"],
  "stream": true
}
Apply 合约：routed = { ...request, model: chosen.model, reasoning: { ...request.reasoning, effort: chosen.effort } }。input、工具定义、工具调用 ID、stream 标记与其余请求字段原样保留；service_tier 不暗中改写。
06

请重点 Review 的三个决定

这些决定影响能否从已通过的可行性测试走向稳定自动路由。

R1 · TRANSPORT

认证 caller edge 的契约

确认验证通过的是哪个版本和入口；明确认证归属、请求头转发、取消传播与 caller edge 升级时的兼容测试。该入口必须绕开 jev/auto 再路由。

R2 · ROUTING SIGNAL

隐私与决策信息量

在不发送原文的前提下，确定哪些结构化事实足以让 Jev 区分简单跟进和困难推理。若事实不足，该次调用使用可靠组合，并在 shadow 数据中量化比例。

R3 · QUALITY + COST

激活标准

先在 shadow 模式记录延迟、提议组合和故障；再用相同任务与验收标准做配对执行，计入 Jev、缓存损失与返工。只有质量达标才讨论总成本收益。
