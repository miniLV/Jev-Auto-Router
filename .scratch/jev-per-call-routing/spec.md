# Spec：Jev 自动切换同一 Codex 会话中的 Model Call（方案 A）

Status: ready-for-agent

## Problem Statement

一个 Main Task 内会连续发生难度不同的 Model Call。用户希望在同一 Codex 会话中，由 Jev 为每次调用选择可请求的模型与推理档位，同时保留工具循环、流式响应、认证、手动选模与隐私边界。现有原型虽有逐调用 Responses Proxy，但其运行时拓扑、默认回退及规范文档仍对应旧方案；用户报告的 A→B→A 实机会话测试通过，还需要把该结果沉淀成可重跑证据，并让产品入口、实际执行与观测使用同一契约。

## Solution

用户在 Codex 中选择虚拟模型 `jev/auto` 后，Codex Router 把每次原生 Responses 请求送到本地 Jev Router。路由器只向 Jev 发送获准的 Routing State 和当前认证入口实测可请求的 Candidate Pair；Jev 通过一次 Choice 提出一个组合。本地 Guard 检查硬约束与回答有效性，Apply 仅修改本次请求的模型和推理档位，再通过已认证的 caller edge 调用真实模型。原生 SSE 或 JSON 响应立即返回 Codex；Codex 自己继续执行工具，下一次 Model Call 重新选路。

用户手动选择真实模型时直接走正常通道。自动路由关闭、信息不足或 Jev 故障时，虚拟模型调用使用事先实测的可靠 Fallback Baseline，并记录原因。任务结束时依据实际执行记录与独立验收结果评价质量和总成本。

## User Stories

1. 作为 Codex 用户，我希望为任务选择 `jev/auto`，以便在同一会话中开启逐次 Model Call 自动路由。
2. 作为 Codex 用户，我希望工具结果后的下一次 Model Call 可以换模，以便任务各阶段使用合适的能力。
3. 作为 Codex 用户，我希望换模时保留原会话上下文与工具调用 ID，以便 Codex 可以继续现有工具循环。
4. 作为 Codex 用户，我希望首个流事件在生成结束前显示，以便维持原生流式体验。
5. 作为 Codex 用户，我希望在任意新请求中手动选择真实模型，以便直接控制该请求的执行模型。
6. 作为 Codex 用户，我希望关闭自动路由后 `jev/auto` 仍可按已验证组合执行，以便遇到故障时继续任务。
7. 作为 Codex 用户，我希望取消调用能停止 Jev 等待或真实上游生成，以便避免无用的等待和计费。
8. 作为 Codex 用户，我希望原始指令、文件内容、工具输出和认证凭据不发送给 Jev，以便路由不扩大敏感内容的接收范围。
9. 作为 Codex 用户，我希望路由事实不足时使用明确的固定组合，以便缺少信息不会触发猜测式切换。
10. 作为 Codex 用户，我希望 Jev 超时、回答无效或信心不足时获得可预测的回退，以便单次路由故障不阻断任务。
11. 作为 Codex 用户，我希望上游已经开始输出后的故障如实呈现，以便避免自动重放导致重复工具动作或重复计费。
12. 作为 Codex 用户，我希望基础设施调用和其他路由权威下的请求不参与 Jev 选路，以便不会产生冲突的控制链。
13. 作为维护者，我希望每个 Candidate Pair 都在当前 caller edge 上实测可请求，以便不会把模型目录展示误当成可执行能力。
14. 作为维护者，我希望分别看到 Jev 提议、Guard 应用和上游报告的实际组合，以便识别传输错配与虚假切换。
15. 作为维护者，我希望记录 Jev 版本、路由原因、耗时和未知用量，以便审计决策并避免把缺失数据当作零成本。
16. 作为维护者，我希望先在 Shadow Mode 观察选择和延迟，再开启实际切换，以便基于数据确定版本与信心门槛。
17. 作为维护者，我希望能复现 A→B→A 的真实 Codex 工具循环，以便在 Codex Router、caller edge 或模型升级后发现兼容性回归。
18. 作为维护者，我希望验证流式透传、取消和会话压缩后的继续执行，以便确认路由器没有破坏 Responses 协议行为。
19. 作为维护者，我希望把路由提议与最终交付结果分开评价，以便 Jev 的信心分数或模型自报完成不被当成任务质量。
20. 作为维护者，我希望自动路由与固定组合在同任务、同仓库状态、同验收标准下比较，以便判断切换是否真的节省完整成本。
21. 作为维护者，我希望上游认证与 Jev 密钥保持分离，以便路由服务无法获取 Codex 的会话凭据。
22. 作为维护者，我希望只有 `jev/auto` 会进入 Jev Router，且转发上游使用真实模型 ID，以便避免请求递归进入自动路由。

## Implementation Decisions

1. **入口与路由单位。** 继续以 Model Call 为单位。Codex Router 仅将虚拟模型 `jev/auto` 交给 Jev Router；用户选定的真实模型由原有通道直接处理。Jev Router 不创建 Main Task、worker 或第二套工具循环。
2. **认证链路。** Jev Router 的上游是已经通过真实会话测试的认证 caller edge。对该入口的每次请求必须带真实模型 ID，且不得递归回到虚拟模型。上游认证由 caller edge 承担，Jev 密钥与上游凭据分离。
3. **候选与输入。** Candidate Pair 是当前认证入口已经实测可请求的 `(model, reasoning_effort)` 组合，并受用户要求和能力约束过滤。Routing State 只含白名单中的结构化事实；原始 prompt、文件内容、工具输出及凭据均不发送给 Jev。事实不足时走明确回退。
4. **选择与 Guard。** 每次获准调用只使用一个固定版本 Jev 的一次 Choice。Guard 校验候选成员、可用性、硬约束、版本与经 Shadow Mode 校准的信心门槛。无效回答只触发固定回退；本地逻辑不增加第二个语义选模器。
5. **Apply 与协议。** Apply 只改本次原生 Responses 请求的 `model` 和 `reasoning.effort`。输入、工具定义、工具调用 ID、流式标志及其他字段保持原样；不暗中修改服务档位。SSE 事件和 JSON 响应原样传回 Codex。
6. **关闭与故障。** `jev/auto` 的 OFF、隐私拒绝、信息不足、Jev 超时、无效回答与低信心均使用同一事先实测的可靠 Fallback Baseline，并记录不同原因。固定组合不可请求则在输出前明确失败。输出开始后不自动换模重放；取消信号传播至等待中的 Jev 或上游。
7. **观测契约。** 分别记录 Jev 提议、实际应用和上游可观察的执行组合，以及 Jev 版本、模式、回退原因、延迟、用量、缓存和结束状态。无法观察的模型或用量标为 UNKNOWN；记录与展示不得改变原生响应流，默认不保存原始文本或密钥。
8. **发布路径。** 首先归档真实 A→B→A 证据并固定认证入口；随后完成直通与固定转发、Shadow Mode、Active 路由和任务结果对照。候选扩容、版本升级和信心门槛调整需重新验证。
9. **规范迁移。** 本 spec 选择方案 A，需要显式修订现有产品规范、运行时策略和 ADR 0017 后再按新契约实施。ADR 0017 的逐调用、单次 Choice、流式透传和任务边界验收继续成立；其旧拓扑、Terra/medium 默认回退及 OFF 恢复原宿主模型的规则与此方案冲突，不能混合执行。

## Testing Decisions

1. **主要接口。** 以 Codex Router 入口到本地 Jev Router、再到认证 caller edge 的完整 HTTP Responses 往返作为最高层测试接口。观察入口请求、真实上游收到的组合、Codex 收到的响应及执行记录，不断言内部辅助函数调用。
2. **确定性集成测试。** 使用受控 Jev 和上游替身覆盖有效选择、用户直通、OFF、隐私拒绝、事实不足、低信心、超时、版本不符、不可请求候选、上游故障、取消与非递归约束；每例断言最终真实上游的模型与 effort。
3. **协议行为。** 验证首个 SSE 事件在完成事件前抵达客户端，事件内容与顺序不变；取消能停止上游；输出开始后不会产生第二次模型请求。验证工具 ID、上下文延续和压缩后的继续执行。
4. **隐私与记录。** 用带敏感标记的请求检查发给 Jev 的事实白名单和默认日志内容；核对提议、应用、观察三个组合分列，未报告的模型或用量保持 UNKNOWN。
5. **实机门槛。** 已保存用户提供的 Codex A→B→A 传输验收摘要：三次调用实际使用 `gpt-5.5 → gpt-5.6-sol → gpt-5.5`，工具结果 ID 延续，认证成功，HTTP 增量先于完成事件送达 CLI 连接，独立 `npm run typecheck` 退出码为 0。还需归档运行版本、认证入口、原始记录和可重跑命令，并在关键升级后重跑；摘要未独立证明 effort 一致性、取消、压缩或终端逐字显示。
6. **价值验证。** Shadow Mode 先测选择分布、事实不足率、失败率和路由延迟。Active 后以等价验收的配对 Main Task 比较完成率、返工及包括 Jev、缓存、重试和验证在内的完整成本；没有可靠用量或质量证据时不宣称节省。
7. **现有测试先例。** 仓库已有 Responses 代理、执行契约、Jev 适配、策略 Guard 与隐私行为测试；扩展这些测试的外部行为覆盖，以完整请求链路为主要验收点。

## Out of Scope

- 按新 turn 切换、Pi 扩展、worker 分派或把工具本身交给 Jev 选路。
- 外部提供商自动重试、额度绕行、输出流内容改写、输出开始后的跨模型重放。
- 在线学习、动态价格优化、复杂粘滞度策略、未经实测的模型自动扩容。
- 仅凭低价模型调用占比、历史 token 重计价或 Jev 信心分数宣称质量和节省。

## Further Notes

- 用户提供的 A→B→A 传输验收摘要已保存在本地证据文件中。它足以支持继续拆票和实施准备；要把完整 ADR P0 标为通过，仍须补齐摘要未展示的检查和可复跑记录。
- 传输可行不等于 Jev 有足够信息作出好选择。若隐私边界内的 Routing State 经常不足，先扩大经授权的结构化事实来源或缩小自动路由覆盖，再决定是否上线 Active。
- 现有规范在正式迁移前仍是仓库当前权威。本 spec 是方案 A 的目标契约；实施的第一步是消除冲突并建立单一运行时策略。
