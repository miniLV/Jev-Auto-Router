# 24 — 在配对运行前冻结任务、评审方法与放行门槛

**What to build:** 维护者在任何固定基线/自动路由配对任务开始前保存一份不可事后改动的评估计划，明确等价输入、独立质量评审、完整成本和通过规则。

Blocked by: None — can start immediately.

Blocks: 25 — 执行真实配对评估并形成发布决定；07 — 配对评估 Main Task 质量与完整成本。

Status: ready-for-agent

Execution readiness: agent 可以先准备计划结构和拒绝测试；真实任务、仓库快照、独立评审者、当前 pair/版本及价格来源须由维护者提供并在运行前冻结，缺失时不能结票。

Related: 原 Issue 07 第 1 项；`bench/paired-evaluation.ts` 的 `EvaluationPlan`；`bench/README.md`。

## Problem

评估器已定义计划结构和时间检查，但仓库尚无针对本次真实运行预先冻结的任务集合、仓库状态、验收、独立评审方法及阈值。运行后再写计划会使质量/成本结论不可审计。

## Solution

1. 选定代表目标工作负载的 Main Task 集合；每个任务固定不含敏感原文的意图摘要、仓库快照、原始验收条件、缓存条件、基线先跑或策略先跑的随机顺序及种子。记录任务纳入/排除准则，避免只保留成功案例。
2. 预先定义独立评审者/方法、质量评分表、完成与返工判定、关键失败与接管判定，以及每个指标的最低值和可容忍回退。评审者不得以 Jev 置信分或模型自报完成代替交付证据。
3. 冻结完整成本口径：每个上游 Model Call、Jev Choice、重试、纠正、验证、缓存读写和 caller-edge 开销；注明价格来源、货币、计费权重和 UNKNOWN 处理。
4. 将计划与执行代码/策略/Jev/caller-edge/候选目录版本及精确 pair 清单绑定；在第一条评估 arm 开始前保存时间、摘要和独立可核对的版本记录。执行期间若要改阈值或任务集合，须创建新计划/新批次，旧运行不混用。
5. 用现有评估器对空、重复、缺失或晚于运行开始的计划做拒绝测试；文档给出如何检查“计划早于数据”。

## Acceptance criteria

- [ ] 真实配对运行前已有冻结且可核对的任务清单、顺序、仓库快照、验收、评审方法、成本口径和门槛。
- [ ] 两个 arm 对每项任务使用等价输入和相同验收标准，执行顺序按冻结计划。
- [ ] 事后修改计划、缺失关键字段或价格 UNKNOWN 时，评估不能宣称通过或节省。

## Boundaries and verification

本票只冻结协议，不提前填写运行结果或 PASS 标志。若实际任务素材尚未准备好，本票不能用纯合成 fixture 结项。运行评估器定向测试与 `npm test`、`npm run typecheck`。

## 预注册交付清单（2026-09-24 细化）

这张票与 08/21–23 **没有代码依赖，可独立准备**；完整冻结仍依赖维护者提供真实任务、仓库快照、独立评审、当前运行绑定和价格来源。必须在 Issue 25 的第一条 baseline、Shadow 或 policy arm 开始前完成。用户此前明确表示真实任务素材、仓库快照和独立评审人尚未准备；Luna 可以准备结构化空白模板与验证，但不能把模板或合成 fixture 标记为本票通过。

08/21–23 的先行传输试验可以独立采证；若其运行早于本票冻结，不得事后把它们改称 Issue 25 的配对 arm 或质量/成本样本。

1. **任务与样本。** 由维护者提供真实、代表目标工作负载的 Main Task 集合；逐项冻结匿名 task ID、无敏感意图摘要及其 digest、仓库 revision/快照 digest、原始验收 ID、纳入/排除规则、失败和未完成任务是否计入分母。任务执行材料在私有位置保存；公开清单只留可核验摘要。不能运行后剔除困难任务。
2. **等价性与顺序。** 明确每项任务的 baseline/policy 起点、输入摘要、仓库恢复方式、同一验收标准、冷/热缓存条件及污染控制；冻结随机种子和每项 `first_arm`。Shadow 的起点和顺序也预先说明。若环境无法复位到等价状态，该任务不产生因果成本/质量结论。
3. **独立评审。** 在运行前确定与执行者分离的评审人或可审计评审流程，冻结评分表、完成/接受判定、返工轮次、根代理接管、关键失败、diff/test/artifact 的引用规则和争议处理。评审人应盲于 arm/路由策略，在盲法做不到时记录偏倚；Jev 置信度和模型自报不算质量证据。
4. **门槛。** 把现有 `EvaluationPlan.gates` 六项阈值填成有单位、有方向的数值：最低质量分、最大完成率回退、最大质量回退、每任务新增返工上限、额外接管率上限、policy/baseline 完整成本比上限。固定统计分母、缺失数据处理、候选逐 pair 放行规则，不能事后调阈值救结果。
5. **完整成本。** 冻结币种、价格来源与时间、完整价格表/权重摘要、Jev 与每个上游物理调用的用量口径、缓存读/写、重试、纠正、验证、失败和 caller-edge 费用；只有来源能证明免费才记 0。缺权威用量或价格写 `UNKNOWN`，不得用估算数宣称节省。
6. **运行绑定。** 冻结 release、Jev 请求/实际固定版本、策略/问题 schema、confidence floor/deadline、caller-edge ID、proof manifest 和派生目录 ID、Fallback Baseline、每个精确候选 pair、运行代码 revision，以及评估计划的独立时间戳和字节摘要。现行 question schema 应从当前运行时读取，不复制旧报告。改任务、门槛或版本就新建计划/批次，不能混用旧 arm。
7. **可审计冻结。** 在首个 arm 前将脱敏计划写入可核对的不可变提交或等价时间戳记录，保存完整私有任务材料与公开摘要的对应规则。现有评估器应拒绝空、重复、缺字段、冻结晚于运行、顺序不符和成本 `UNKNOWN` 的 PASS/节省结论；只在发现具体缺口时补最小行为测试。

## Root review 门槛

- [ ] 真任务、仓库快照、独立评审主体及方法、顺序、阈值、价格和所有 runtime 绑定**均在首个 arm 前**冻结；Root 能核对冻结时间与摘要。
- [ ] 每个 arm 的输入、验收、缓存和起点等价性有操作步骤；失败任务不会被排除，缺价/缺用量不会成为零成本或节省。
- [ ] Luna 输出预注册计划、私有材料索引（只含脱敏引用）、定向评估器验证、`npm test` / `npm run typecheck`。缺任务/评审人时只提交标明未完成的准备工作，本票不得 `resolved`，不得启动 25。
